# Проверка безопасности Simonov Tech — 11 октября 2026

Область: только репозиторий `simonov_tech`. Исходный отчёт
`application-security-audit.html` рекомендовал CSP/HSTS для статического сайта.
На текущем HEAD используется Nginx; Caddy, игровые API, PostgreSQL
и общий Traefik не являются зависимостями этого репозитория.
Исправления A01–A09 для других приложений и хоста здесь не выполнялись.

## Исправления

- Добавлена CSP в HTML: скрипты только с собственного origin, запрет
  встроенного JavaScript, eval, объектов, сетевых запросов из JS,
  изменения base URL и отправки форм. Сохранены Google Fonts,
  локальные изображения, SVG через data URI и inline CSS анимаций.
- Инициализация класса `js` перенесена во внешний файл. Проверка сайта
  отвергает inline script и обработчики событий в HTML.
- Конфигурация Nginx добавляет CSP с запретом встраивания сайта,
  X-Frame-Options DENY и HSTS на год без includeSubDomains/preload.
- Дополнительно найден риск прежнего локального запуска:
  `python3 -m http.server` слушает все интерфейсы и обслуживает весь
  каталог репозитория, включая служебные файлы. Новый preview слушает
  только 127.0.0.1, отдаёт временную копию публичных файлов и запрещает
  листинг каталогов. Скрытые файлы и symlink отвергаются до копирования.

Подтверждённого нового пути эксплуатации опубликованного сайта при
проверке HTML/JS, публикации и конфигурации не найдено. Отсутствие CSP
в исходном отчёте было рекомендацией усиления, а не доказанным XSS.

  через `node --check`, XML SVG; 10 публичных файлов.

  включая публикацию/откат, закрытые пути preview, запрет листинга,
  symlink/hidden files, inline JS и согласованность CSP HTML/Nginx.

## Ограничения и применение

Сборки приложения, npm/Go-зависимостей и proto/codegen здесь нет.
Полный scan OS packages образа и серверной инфраструктуры не выполнялся.
Production конфигурации и production HTTP/TLS этой локальной проверкой
не удостоверены. Атакующий трафик на production не отправлялся.

CI публикует только index.html/css/js/assets: CSP из HTML попадёт в обычную
публикацию, но HTTP-заголовки требуют отдельного применения
`deploy/nginx.conf` администратором и проверки Nginx на сервере.
Запрет frame-ancestors не поддерживается в meta CSP, поэтому он задан
именно в HTTP-заголовке. HSTS необходимо проверять через публичный HTTPS.
Inline CSS остаётся разрешённым для существующего оформления.

Правила проверены по [документации Nginx](https://nginx.org/en/docs/http/ngx_http_headers_module.html),
[MDN CSP](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Content-Security-Policy)
и [MDN HSTS](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Strict-Transport-Security).
